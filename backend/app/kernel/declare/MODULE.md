# declare

- Interface: `registry.operation(name, Declares)` is how a module declares an operation, and `dispatch(ctx, Call) -> Committed | Replayed | Denied | WaitingApproval` is the one way one runs. Under it, `commit(session, Commit) -> Action` and `append(session, Append) -> Event`, both inside the caller's transaction, both reading the org from the session; the ledger is the only writer of `event` and `action`.
- Order of checks: the operation exists, the idempotency key is reserved (a key that already names an action is `Replayed` and nothing runs), the principal's grant (from `identity.effective_grants`, read once per dispatch) is `may_use` or `asks_first`, the args parse, an operation with an aggregate was given an `expected_version`, and only then does an `asks_first` call reach its approval. Every refusal deletes the reservation, appends a `denial` event and returns `Denied`, so a call that did nothing is as readable as one that did. The body and its commit run in a savepoint: a version conflict loses the body's writes and keeps the transaction. A read commits nothing, bumps no version, and leaves a `read_audit` event.
- Approvals: an `asks_first` write names its action before the savepoint opens, because `action` is append-only and the row has to carry `approval_id` in its INSERT; inside the savepoint it consumes the approval against that id, runs the body and commits, so a version conflict rolls the consume back with the writes and leaves the approval open. An `asks_first` read consumes before it runs and names no action (`consumed_by_action_id` stays NULL, and the only trace is the `read_audit` event). No open approval: the call parks, the reservation stays open so the same key resumes it, and `WaitingApproval(approval_id, expires_at)` is returned; a continuation already rejected or expired deletes the reservation and returns `Denied("approval_unavailable")` with the state and reason in the payload, which becomes the tool result. A call made outside a run has no continuation to park at and is `Denied("approval_required")`. Expiry is read through `ctx.clock`, the one wall clock dispatch touches. An operation that declares no aggregate is unversioned: its commits take the next version of its own operation stream with no check, and `expected_version` on the call is ignored (ADR-0017).
- Role: each switches the connection to `agentquilt_ledger_writer` for its writes only and back to `agentquilt_app` before returning: the writer role reads and appends, the app role only reads, and neither may update or delete `event` or `action`.
- Raises: `VersionConflictError(expected, actual)` when `expected_version` does not match `stream_head`, read under a row lock before anything is written, so the caller's transaction survives the conflict and its rollback loses nothing else; a repeated idempotency key returns the stored `Action` and writes nothing, and a reservation (`action_id` NULL, written by dispatch before the operation runs) is completed by `commit()` rather than inserted a second time, so a call that was parked and resumed keeps its one key.
- Mapped: `event`, `stream_head`, `operation_version`, `action`, `idempotency_key`, column for column with migrations 0001 and 0002; the deferred `fk_event_action` is what lets one transaction write the event and its action in that order.
- Not built: expiring a `requested` approval and re-queueing its step (wave 8's tick), running a compensator, and any read model over the ledger.
