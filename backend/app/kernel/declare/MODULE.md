# declare

- Interface: `registry.operation(name, Declares)` is how a module declares an operation, and `dispatch(ctx, Call) -> Committed | Replayed | Denied` is the one way one runs. Under it, `commit(session, Commit) -> Action` and `append(session, Append) -> Event`, both inside the caller's transaction, both reading the org from the session; the ledger is the only writer of `event` and `action`.
- Order of checks: the operation exists, the idempotency key is reserved (a key that already names an action is `Replayed` and nothing runs), the principal's grant is `may_use`, the args parse, and an operation with an aggregate was given an `expected_version`. Every refusal deletes the reservation, appends a `denial` event and returns `Denied`, so a call that did nothing is as readable as one that did. The body and its commit run in a savepoint: a version conflict loses the body's writes and keeps the transaction. A read commits nothing, bumps no version, and leaves a `read_audit` event.
- Role: each switches the connection to `agentquilt_ledger_writer` for its writes only and back to `agentquilt_app` before returning: the writer role reads and appends, the app role only reads, and neither may update or delete `event` or `action`.
- Raises: `VersionConflictError(expected, actual)` when `expected_version` does not match `stream_head`, read under a row lock before anything is written, so the caller's transaction survives the conflict and its rollback loses nothing else; a repeated idempotency key returns the stored `Action` and writes nothing, and a reservation (`action_id` NULL, written by dispatch before the operation runs) is completed by `commit()` rather than inserted a second time, so a call that was parked and resumed keeps its one key.
- Mapped: `event`, `stream_head`, `operation_version`, `action`, `idempotency_key`, column for column with migrations 0001 and 0002; the deferred `fk_event_action` is what lets one transaction write the event and its action in that order.
- Not built: `approval_id` and the approval an `asks_first` grant will raise instead of a denial (wave 5, identity), running a compensator, and any read model over the ledger.
