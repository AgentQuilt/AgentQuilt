Wave 5: identity and approvals

~450 lines (estimate) · clauses 4, 5, 6

  • identity.resolve(token) → principal; identity.effective_grants(principal, agent_definition) → Ceiling as a pure function over core.grant rows (no port, ADR-0026); the per-step definition from ADR-0015:18 (root ceiling ∩ narrowing state ∩ acting principal's grants), with narrowing state always empty in Phase 1.
  • args_hash = SHA-256 over "agentquilt.approval.v1" || operation_version_id || canonical JSON of args || target scope (RFC 8785 canonical form via the library Context7 names).
  • Dispatch integration: level asks_first first tries the consume-once UPDATE … WHERE org_id AND granted_to AND operation_version_id AND args_hash AND state='open' AND expires_at > now() RETURNING inside the commit transaction; one row → the call commits with the action naming the approval; zero rows and no requested or rejected row for this (run_id, step_no, tool_call_id) → insert an approval in state requested with the continuation identity and return waiting_approval; zero rows and a rejected or expired row → denial(approval_unavailable), the reason becomes the tool result and the step continues. Expiry by tick re-enqueues the step exactly as a rejection does (wave 8). A grant-level never or a missing grant is denial with the same continuation: tool result, step continues.
  • governance.decide(approval_id, approve|reject, reason) as a declared operation, the first module operation. Approve moves requested → open with granted_by = the deciding user; reject moves requested → rejected with the reason. Both act only on a requested row. In the same transaction it runs UPDATE run SET state = 'queued' WHERE id AND state = 'waiting_approval' RETURNING id and inserts the step_queue row for the same (run_id, step_no) only when that update returned a row; a cancelled run (whose approvals cancel already expired) is refused before either statement. The worker resumes from the journaled plan and replays the parked call under its original idempotency key: the open reservation resumes, the consume-once statement finds the open row (approve) and commits, or finds none and writes denial(approval_unavailable) with the rejection reason as the tool result (reject). No other continuation state exists.

Accept: test_grant_checked_at_call_time, test_asks_first_opens_approval, test_approval_binds_to_digest (changed args → denial), test_approval_consumed_once (two concurrent consumers, one wins), test_expired_approval_denied (clock injected).
